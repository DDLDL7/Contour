# Contour interface review — 11 October 2026

## Verdict

Contour has a credible, restrained visual identity for a student maths tool. Mathematical typography, graph paper, colour-linked expressions and quiet controls fit the product. Keep that direction. The biggest opportunity is reducing the decisions and duplicate controls between the student and their work.

The first equation-to-graph experience works well. The broader workspace still exposes too much of its feature structure. This is an expert review, not evidence that students want to use it; student sessions remain a release gate.

## What works

- Entering an equation gives immediate graph feedback, with colour connecting the two.
- The restrained appearance suits focused study and has a recognisable mathematical character.
- Local saving is reassuring on wide screens; Help closes with Escape and restores focus.

## Priority issues

1. **P1 — Save failures become invisible at narrower widths.** `src/redesign.css` hides `.save-status` below 1540px and history controls below 1180px. `src/App.tsx` uses that same status element for save-failure guidance. This weakens trust and can conceal a problem protecting work. Keep compact saving/error feedback and Undo visible; move lower-frequency actions into overflow first. The hidden status was observed at zoom; the failure-state consequence is source-confirmed, not a simulated storage failure. Suggested command: `$impeccable adapt`.

2. **P1 — Maths Tools asks students to understand overlapping tool families.** Quick/numerical methods include operations also offered under Exact Symbolic and Differential Equations. The numerical selector alone has 20 methods across three groups. A student knows they want to differentiate, not which engine to choose. Organise by mathematical task, with Exact/Approximate options where relevant. Preserve drafts across method/view changes. Source inspection additionally identifies component-local drafts reset on unmount and a global Undo handler that intercepts text-field Undo; those need focused browser reproduction before being described as observed failures. Suggested command: `$impeccable clarify`.

3. **P2 — Two expression panels compete with the graph.** The desktop shell repeats expressions in a summary rail and editable panel; the empty screen offers five Add-expression buttons. The graph receives under half the initial width. Use one editable expression panel by default and make the summary optional. Reveal parameters when relevant or requested. Keep one primary Add action and a contextual empty-state action. Suggested command: `$impeccable distill`.

4. **P2 — Notebook starts with the authoring toolbox.** Nine cell-add buttons appear before the content, plus an empty-state Add-first-note action. A newly added note can land below the fold at zoom without focus or scrolling. Lead with Note, Calculation and Graph; put less common and interactive cells in a labelled menu with short descriptions. Focus and reveal newly inserted cells. Preserve the single **Activity templates** dropdown requested for the product. Suggested command: `$impeccable onboard`.

5. **P2 — Spreadsheet row 1 is easy to mistake for data.** Analysis starts at row 2, but row 1 looks like an ordinary row and the initial instruction only says to enter A/B pairs. A student can silently exclude their first pair. Mark row 1 as headers and explicitly direct data entry to A2/B2. Suggested command: `$impeccable clarify`.

## Cognitive load and emotional journey

Load is moderate overall and high within Maths Tools and Notebook. Minimal choices, progressive disclosure and focusing on one decision at a time need work. The five workspace tabs are reasonable; raw option counts alone do not prove a usability failure.

The first rendered curve provides a satisfying success. Momentum drops when users must classify a maths operation or choose among authoring controls before writing. Wide-screen autosave provides reassurance; removing that feedback at zoom undermines the ending of the workflow.

## Persona checks

- **Jordan, first-time student:** Can plot a first curve, but duplicate expression lists, an unused parameter, engine choices and spreadsheet row 1 create avoidable questions.
- **Alex, frequent user:** Benefits from direct entry and shortcuts; loses graph area to repeated information. Tool draft preservation needs focused verification and improvement.
- **Sam, keyboard/zoom user:** Help focus and Escape work, but save feedback and visible Undo disappear at zoom. This does not substitute for a VoiceOver or full accessibility audit.

## Minor observations

Help is primarily a long graph reference. Add short guidance within each workspace. Replace implementation-oriented labels such as “Active rail” with student-facing language. Small serif labels merit a legibility pass while preserving the established typography. A 3D item in the shared expression rail may have no matching editor to scroll to in 2D; this is a source-supported risk, not a reproduced click failure.

## Detector and evidence

The single detector run reported one `side-tab` warning at `src/styles.css:237`, the left border on `.notebook-preview`. The border distinguishes preview content; the generic-style interpretation is a contextual false positive, not a priority defect. No other detector findings were reported.

Reviewer A inspected all five workspaces in native Chrome, entered a plotted expression, ran a calculation, entered spreadsheet pairs, inserted a note and created a sphere. A also checked 175–200% zoom and restored normal zoom. Reviewer B independently inspected the initial graph and accessibility-tree states for Maths Tools and Notebook and imported a review fixture. Later native browser automation became unreliable (stale screenshots, stale indices and `noWindowsAvailable`), so follow-up text-Undo testing was inconclusive. Real touch hardware, VoiceOver and complete light-theme coverage remain unverified. No software was installed for this review.

## Design decisions

- Should the default graph have one editable expression panel with an optional summary, or retain three columns?
- Should Notebook lead with Note, Calculation and Graph, or expose all authoring controls immediately?
- Should each maths task have one entry point with exact/approximate settings? The review recommends this task-first arrangement.
